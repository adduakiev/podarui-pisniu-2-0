# Shared asynchronous dialogue entrypoint

Base: 1b76e40f4d0fe72164eabfbae6e4d0c3c3b50509 / d8f386c01ec90bbbfcb3613552bff578a080b8f1. This slice preserves payment terms and only changes dialogue ingress and adapter orchestration.

Site POST, Telegram and Instagram Direct use processInbound -> olenaDialogue -> injected interpreter or configured Responses interpreter. Direct validates signature/account/echo before atomic lead binding, inbound claim and original text persistence. Telegram persists sanitized input in its delivery record. The common dialogue_inbound journal records channel, event ID, order ID, original input and received time before interpretation. No network await runs inside a SQLite transaction. Adapter snapshots are read-only and cannot reapply a still-pending opening. Delivery revision is captured by the synchronous conversation result, not after an async continuation.

Adapters retain their existing dedupe and transport semantics. Conversation reservations guard arrival order and revision; stale model results are log-only and suppress outbound. Delivery-time revision checks prevent sending an obsolete reply after a later handoff/stop/correction. Producer/no-contact paths bypass interpretation. A handoff acknowledgement is allowed once; later automatic replies are suppressed. Changed inbound ID reuse is rejected by the shared entrypoint. Same in-flight site request reports INBOUND_IN_PROGRESS; a completed retry uses the stored result and cannot undo a newer producer lock.

Interpretation exceptions use the deterministic fallback while preserving the inbound. Unknown transport outcomes are retained for review and never blindly resent. A process crash with a processing/preparing claim is intentionally not automatically reclaimed; an operator must reconcile before any replay. This avoids duplicate sends but is not a background queue/recovery service. Direct raw inbound is retained in instagram_inbound_payloads even if processing stops before the common call. No real sends were tested.

Model selection is disabled by default. Enabling requires OLENA_RESPONSES_ENABLED=1, OPENAI_API_KEY, OLENA_MODEL_CANDIDATE set explicitly to luna/terra/sol and its corresponding OLENA_MODEL_LUNA/TERRA/SOL mapping. No model ID is silently selected. Astra candidate or a mapping containing Astra is rejected. Injected interpreters require no credentials and are used by all tests.

Checks: node --import tsx --test tests/*.test.ts; npm run typecheck; NEXT_TELEMETRY_DISABLED=1 npm run build. tests/channel-dialogue.test.ts uses only synthetic Ukrainian text, fake transports and temporary DBs; covers all three channels, correction, duplicate/in-flight retries, concurrent newer corrections, failure retention, stop/handoff races, uncertain delivery and model configuration. The historical 858-test suite was not supplied; only the available suite is claimed.

Reusable practice: persist the inbound and claim its identity atomically before awaiting an interpreter; validate revision again before delivery. Tests assert db().isTransaction=false inside every injected interpreter/transport and verify that a delayed 'Хочу пісню для мами' cannot overwrite 'Не для мами, а для бабусі' or speak after 'Покличте менеджера'. Sources are existing conversation reservation and adapter outbox contracts in this repository; this slice retains those contracts across the async boundary.

No production configuration, transport credentials, model rollout, main, merge or Notion changes are included. Cross-channel live quality and process-crash recovery remain separate release gates.

Operator reconciliation is now available in `/admin/recovery`; see `docs/crash-recovery.md` for leases, protected recovery and review-only uncertain delivery. Historical author evidence for this slice remains unchanged.
