Перевірку продовжено через Codex browser та окремий API-скрипт. `browser-check.mjs` — допоміжний незавершений сценарій, не перевірений регресійний тест. API-скрипт залишає тестовий файл чернеткою; браузерна перевірка залишає одне явно тестове замовлення.

Не перевірено/не реалізовано: Supabase/Vercel deployment, MFA, реальні платежі/webhooks, резервування/відновлення, приватні версії файлів замовлення, повні групи сторіс із окремими обкладинками, відправка клієнтам, реальний пілот.

## Розмова після заявки — 6 жовтня

Прибрано другу кнопку заявки: форма переходить у чат. Додано підписаний доступ до розмови, збереження діалогу, відновлення у браузері, питання за сценарієм із пропуском наявних полів, підсумок та підтвердження. Діалог відображається в нотатках замовлення; правки/строк/оплату погоджує власник. Платіжне посилання береться з адмінки тільки після підтвердження історії. Telegram веде до ручного контакту, WhatsApp має підготовлений текст із номером замовлення; автоматичний бот не підключений.

Три автоматичні тести пройдено, включно з пропуском відомих полів, збереженням діалогу та показом реального призначеного посилання. Браузер: заявка → привітання → шість відповідей → підсумок → погодження → reload → збережена розмова. Попередня production build пройшла; після останніх змін повторено typecheck. API-тест із shell не виконався через мережевий sandbox; замінений модульним тестом і браузером. Чат наразі сценарний; вільне AI-спілкування, автоматична генерація рахунка та підтвердження платежу провайдером не реалізовані.

## Telegram — 6 жовтня

Токен власника перевірено через getMe й збережено AES-GCM локально з правами 0600. Запущено polling worker; getWebhookInfo підтвердив відсутність webhook, старі накопичені повідомлення при першому запуску пропущено. Посилання start містить випадковий код без персональних даних; заявка прив’язується до приватного чату. Відповіді використовують спільний сценарій і записуються в замовлення. TypeScript та три тести пройдено. Реальне проходження від сайту до відповідей у Telegram потребує тесту власником. Polling живе лише доки працює локальний процес. Вільний AI-діалог і повідомлення після зміни платіжного посилання ще не автоматизовані.

## Перший блок менеджера комунікацій — 28 жовтня 2026

Змінено сценарний fallback без підключення нової AI-моделі: розділено питання, явні зміни полів і передачу продюсеру. Питання про MP3, ціну, строки, оплату й правки отримують відповідь без споживання поточного поля; невідоме питання передається продюсеру. Додано чинні умови оплати та п’яти раундів у підсумок. Неповний настрій без голосу потребує уточнення. Явна зміна скидає підтвердження. Повідомлення про оплату передається на перевірку без зміни paid.

Режим producer збережений у замовленні й розмові. Подальші повідомлення клієнта зберігаються без автоматичної відповіді/платіжних кнопок. Відновлення лише через захищений admin endpoint та кнопку в картці. Збереження розмови не скидає статус «Музика» чи інші виробничі етапи. Telegram worker враховує паузу, але запущений процес у цьому кроці не перезапускався.

Пройдено: TypeScript, production build, 8 автоматичних тестів (6 тестів діалогу та 2 попередні тести замовлень/медіа). Тести ізольовані у тимчасовій базі; реальні дані не змінювалися, повідомлення клієнтам не відправлялися. Зовнішня браузерна перевірка цього оновлення й реальний Telegram-тест не виконані. Git status недоступний через відсутність системних developer tools; перевірку версій не позначено пройденою.

Обмеження: це консервативне правило-орієнтоване розпізнавання, не повне розуміння довільного тексту. Автоматичне виділення всіх фактів з великої історії, вільні формулювання змін, повний облік п’яти раундів і відправлення приватного MP3 ще потребують наступних етапів.
